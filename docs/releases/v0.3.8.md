## Annex 0.3.8

Everything since 0.3.6, including the 0.3.7 betas. Thanks to [Saidev Dhal](https://saidev.codes) for the logs and the testing over the internet. **Install it on both computers.**

### Fixed

- **The picture no longer freezes while the pointer keeps moving.** When part of the picture was lost on the way, the viewer asked the other computer for a fresh one only once, and if that was lost too the picture stayed stuck for up to 30 seconds. The viewer now holds the last good picture and keeps asking until a fresh one arrives, usually within a second.

### Improved

- **A steadier picture on a fast connection.** After lowering the quality because frames were lost, Annex used to climb straight back to where they were lost within 3 seconds, and lose them again. It now waits a moment, and climbs slowly near that point.
- **A sharper picture over the internet.** Annex used to lower the picture's quality every time a single frame got lost on the way, and was slow to raise it again, so a good internet connection could look blurry. It now ignores the odd lost frame and lowers the quality only when the connection really can't keep up.
- **Fewer blocky moments.** Each frame carries more repair data, so a short burst of lost packets no longer spoils it.
- **HEVC on every platform.** When both computers support it, the picture is sent as HEVC: sharper at the same speed. Otherwise it's H.264, as before, with nothing to set up.
  - **Mac:** every Apple silicon Mac, and Intel Macs that decode HEVC in hardware.
  - **Windows:** sending needs a graphics card with an HEVC encoder (NVIDIA, Intel or AMD); receiving needs Windows' HEVC decoder (the HEVC Video Extensions, built into many PCs and available from the Microsoft Store).
  - **Linux:** sending needs an HEVC encoder on the graphics chip (Intel and AMD through VA-API, NVIDIA); receiving needs a GStreamer HEVC decoder (gstreamer1.0-libav has one).
  - When several computers watch one screen, it's HEVC only while all of them support it.
  - Turn it off in **Settings → HEVC** if the picture misbehaves.
- **More internet connections go direct, without the relay.** Some internet providers share one public address among many homes, and their routers give each connection its own port. Annex now also connects to the port that computer's router really uses. Nothing new is opened to anyone: it's a path the sharing computer's own router made towards the viewer, and only packets signed with your code can point Annex to it.
- **More direct connections with a code.** Some internet providers forget an idle connection after a minute, so a code that waited a while before the other computer typed it ended up on the relay. While a code waits, Annex now keeps the way in open.
- **The relay is only a fallback, and no longer a lesser one.** Annex uses it only when the two networks block a direct connection. A relayed session now has the same quality as a direct one and no 20-minute limit. Each computer can use it for 10 sessions a day, and the sharing page shows how many are left and shows **Relay** next to a viewer connected through it. When they're used up, they come back at midnight UTC, or add your own relay and server in **Settings → Advanced → Internet**, which have no limit.
- **Clearer logs for internet connections.** If a connection over the internet is slow or goes through the relay, `annex.log` now helps find out why. Attach it to a bug report.

### Still the same

Every session is end to end encrypted (TLS 1.3, checked against each computer's identity), whether it's direct or through the relay. The relay only forwards packets it can't read.
